Set up GA4 and Microsoft Clarity, step by step

GA4 tells you what sold: which destination, which plan, which ad, which code. Clarity shows you why people didn't buy: recordings and heatmaps of real visits. Both go in through Google Tag Manager, so the developer only has to add one piece of code to the checkout. Tick each step as you go; ticks are saved in this browser only.

How the pieces fit

1 · Websitecalafly.netThe site tells Tag Manager what happened: viewed a plan, started checkout, bought.
2 · Tag ManagerOne containerSends each moment to GA4, Google Ads, Meta and Clarity. No more code changes after this.
3 · GA4Sales and sourcesRevenue by destination, plan, campaign, keyword and promo code.
4 · ClarityBehaviourSession recordings, heatmaps, rage clicks, where people drop off.

The site already sends its own moments (INITIATE_JOURNEY, CHECKOUT, CHECKOUT_SUCCESS) to Meta. Part B asks the developer to send the same moments, with the order details, in the standard format GA4 understands.

Reports to read every week

Dailyweek 1, 5 min
  • GA4 → Reports → Realtime: purchases are arriving when Google Ads or Meta show conversions.
  • Clarity → Recordings: watch 3 sessions that reached checkout but didn't buy.
Every Thursday30 min
  • Sales by destination (F2): which country earns the most per £ of ads. Feeds the budget split.
  • Checkout funnel (F3): the biggest drop between steps. That step gets fixed first.
  • Promo codes (F4): share of orders using USA10, TURKEY10, DUBAI10. If it's above 70%, test ads without the code.
  • Clarity heatmap of /usa, /turkey, /dubai on mobile: is the price block seen? Where do taps go?
Monthly
  • Compare GA4 purchases with CalaFly's real order count. More than 15% apart means a tag is missing; check part E again.
